# SSO redirect loop guard

## Scope

Stop the monitoring portal from bouncing users back to the sparta login when
`sso_session` is missing or stale. Sparta now sets `sso_session` after login and
redirects GS straight to monitoring, so an unreadable session would loop.
Production env changes (`NEXT_PUBLIC_SPARTA_AUDIT_URL`, `SSO_COOKIE_DOMAIN`)
and the sparta cookie change are outside this repo.

## Context and Sources

Coordinated with the sparta-energy session. Reviewed `proxy.ts`,
`lib/auth/access.ts`, `app/(dashboard)/layout.tsx`, `app/api/auth/logout/route.ts`,
and `docs/agent-notes/2026-10-26-0920-portal-akses-role.md`.

## Changed Files

- `lib/auth/access-rules.ts`: `BOUNCE_COOKIE`, `BOUNCE_MAX_AGE_SECONDS`,
  `SESSION_DENIED_PATH`, `anonymousPageTarget()`.
- `proxy.ts`: sets `sso_bounce` (60 s) on the redirect to sparta; a second
  anonymous page request within that window goes to `/akses-ditolak?alasan=sesi`.
- `lib/auth/access.ts`: new status `invalid` when the cookie matches no live session.
- `lib/auth/api-guard.ts`: `invalid` returns 401 like `anonymous`.
- `app/(dashboard)/layout.tsx`: `invalid` redirects to `/api/auth/session-invalid`.
- `app/api/auth/session-invalid/route.ts`: clears `sso_session`, redirects to the denied page.
- `lib/auth/session-cookie.ts`: shared `clearSessionCookie()`, also used by logout.
- `app/api/auth/logout/route.ts`: uses the shared helper.
- `app/akses-ditolak/page.tsx`: separate message for `alasan=sesi`.
- `tests/access-rules.test.mjs`: test for `anonymousPageTarget()`.
- `AGENTS.md`, `CLAUDE.md`: documented the loop guard.

## Decisions

A short-lived cookie is used instead of checking Referer, because Referer is
unreliable across 30x redirect chains and cross-origin policies. The stale
cookie is cleared in a route handler because server components cannot set cookies.

## Verification

`pnpm test:access` 7/7 pass; `tsc --noEmit` and eslint on changed files exit 0.
Against the dev server: no cookie gives 307 to sparta `/login` with `sso_bounce`;
with `sso_bounce` gives 307 to `/akses-ditolak?alasan=sesi` and clears it; a fake
`sso_session` gives 307 to `/api/auth/session-invalid`, which clears the cookie and
redirects to the denied page; that page shows "Sesi login tidak valid".

## Remaining Work and Risks

GS users already logged in to sparta before its cookie change ships will land on
the denied page and must sign out and in again. Production needs a rebuild with
the corrected env.
